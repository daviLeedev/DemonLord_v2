# 세계조정국 연구실 세로 슬라이스 구현 프롬프트

## 1. 역할과 목표

당신은 `C:\workspace\unity\DemonLord_v2` Unity 프로젝트를 이어서 개발하는 시니어 Unity 클라이언트 개발자다.

현재 구현된 탐색 이동 프로토타입을 기반으로 다음 플레이 가능한 세로 슬라이스를 완성한다.

```text
타이틀/세이브 진입
→ 세계조정국 연구실의 시작 지점에 세무관 등장
→ 여러 방과 복도를 자유롭게 이동
→ 문을 열고 닫으며 방 사이를 왕복
→ 잠긴 문을 조사하면 잠금 메시지 표시
→ NPC에게 F로 대화
→ 왼쪽에 세무관 초상화, 오른쪽에 대화 상대 초상화가 표시되는 대화창 진행
→ 대화 종료 후 이동·카메라·상호작용 상태가 정확히 복원
```

이번 단계의 핵심은 최종 그래픽 완성이 아니라 다음 요소가 실제 게임 흐름 안에서 함께 작동하는 것이다.

- 세계조정국 연구실 다중 방 맵
- 3D XZ 이동과 결합된 2D/2.5D 캐릭터 표현
- 세무관의 8방향 대기·걷기·달리기·대시 애니메이션
- 열림·닫힘·잠김 상태를 갖는 문
- 양쪽 초상화가 있는 대화 UI
- 실제 세이브 진입점과의 연결
- 이후 실제 맵·캐릭터·초상화·폰트를 안전하게 교체할 수 있는 데이터 경계

커밋과 푸시는 하지 않는다.

## 3. 확정 기술 방향

### 3.1 월드와 이동

- 월드는 3D XZ 평면과 `CharacterController`를 유지한다.
- 카메라는 현재 구현된 직교 투영 쿼터뷰를 유지한다.
- 이동은 카메라 기준 WASD 8방향 자유 이동이다.
- `Left Shift`: 달리기
- `Space`: 대시
- `F`: 상호작용 및 대화 진행
- `Enter`: 대화 진행 보조 입력
- `Escape`: 대화 취소/종료
- `Q/E`: 카메라 90도 회전
- 마우스 휠: 확대/축소
- 새 입력 처리는 기존 `ExplorationInputReader`와 Input System을 통해서만 추가한다.
- `Keyboard.current`, `Mouse.current`, 레거시 `Input` 직접 조회를 게임플레이 코드에 넣지 않는다.

### 3.2 캐릭터 표현

- 물리와 이동은 계속 3D로 처리한다.
- 시각 표현은 카메라를 향하는 2D 스프라이트 기반으로 구성한다.
- 캐릭터 충돌 루트, 이동 루트, 시각 루트를 명확히 분리한다.
- `PlayerFacing`이 스프라이트 오브젝트를 직접 임의 회전시키는 구조를 확장하지 않는다.
- 별도 `DirectionalSpritePresenter` 또는 동등한 Presenter를 둔다.
- 최종 원화가 없어도 기능을 확인할 수 있는 세무관 임시 스프라이트 세트를 만든다.
- 임시 이미지는 최종 에셋인 것처럼 코드에 박아 넣지 말고, 인스펙터에서 실제 스프라이트 세트로 교체 가능해야 한다.

### 3.3 씬 전략

- 현재 세이브 진입 흐름과 호환되도록 `90_GameShell`을 세계조정국 연구실 플레이 씬으로 사용한다.
- 씬 안에 전용 생성 루트 `__WorldAdjustmentLabGenerated`를 사용한다.
- 빌더가 소유하지 않은 오브젝트는 삭제하거나 이동하지 않는다.
- 기존 `__ExplorationPrototypeGenerated`는 새 맵 생성과 검증이 성공한 후에만 비활성화할 수 있으며, 자동 삭제하지 않는다.
- 에디터 빌더는 반복 실행해도 결과가 중복되지 않는 멱등 구조여야 한다.

## 4. 먼저 수정할 기존 탐색 프로토타입 결함

새 기능을 추가하기 전에 다음 문제를 재현하고 수정하며 회귀 테스트를 추가한다.

### 4.1 남아 있는 Escape 입력

현재 탐색 중 누른 Escape가 소비되지 않고 남아 다음 대화를 시작하자마자 닫을 수 있다.

요구사항:

- 대화 시작 전에 대화 컨텍스트와 무관한 오래된 `Cancel` 입력을 제거한다.
- 대화 중 새로 들어온 Escape만 현재 대화를 종료해야 한다.
- 입력을 단순히 매 프레임 전체 초기화하여 정상 입력까지 유실시키지 않는다.
- `Confirm`, `Cancel`, `Interact`, `Dash`의 1회성 소비 정책을 문서화한다.

### 4.2 대화 UI 비활성화 시 잠금 잔류

현재 대화 패널만 비활성화되고 컨트롤러가 살아 있으면 이동·카메라 잠금 핸들이 남을 수 있다.

요구사항:

- 대화 패널, CanvasGroup, NPC 또는 대화 컨트롤러 중 하나가 비활성화/파괴되어도 대화를 안전하게 종료한다.
- 모든 입력 잠금 핸들과 카메라 오버라이드 핸들을 정확히 한 번 해제한다.
- 중복 종료 호출은 안전해야 한다.
- 다음 대화를 다시 시작할 수 있어야 한다.

### 4.3 카메라 회전 시간

- 기본 90도 회전은 약 `0.25초`에 실질적으로 완료되어야 한다.
- `SmoothDamp`의 감쇠 상수를 완료 시간처럼 사용하여 1초 이상 끌지 않는다.
- 시작 yaw, 목표 yaw, 진행 시간을 보간하는 명시적 전환 상태를 권장한다.
- 회전 도중 추가 Q/E 입력 정책을 결정하고 테스트한다. 권장 정책은 입력을 정수 quarter-turn 큐에 누적하되 최종 인덱스를 결정론적으로 계산하는 방식이다.

## 5. 세계조정국 연구실 맵 요구사항

한 씬 안에서 로딩 없이 걸어서 왕복할 수 있는 최소 다중 방 구조를 만든다.

### 5.1 필수 공간

1. **중앙 접수실**
   - `start` SpawnPoint 위치
   - 세무관이 처음 등장하는 장소
   - 세계조정국 표식과 방 안내판을 둘 수 있는 자리

2. **세무관 업무실**
   - 책상, 서류 보관대, 조사 가능한 오브젝트 최소 1개

3. **세계선 분석실**
   - 대화 가능한 연구원 NPC 배치
   - 분석 장치 또는 마법진 형태의 조사물 최소 1개

4. **기록 보관실**
   - 서가와 좁은 통로
   - 카메라와 충돌이 불편하지 않도록 통로 폭 검증

5. **격리 연구실**
   - 현재는 잠긴 방
   - 문과 방 내부는 존재하지만 정상 플레이로 진입할 수 없어야 함
   - 문을 조사하면 `접근 권한이 없습니다. 문이 잠겨 있습니다.` 메시지 표시

### 5.2 연결 구조

- 중앙 접수실을 허브로 삼아 복도와 문을 통해 나머지 방으로 이동한다.
- 최소 4개의 실제 작동 문과 1개의 잠긴 문을 둔다.
- 방 사이를 여러 번 왕복해도 카메라, 입력, 문, 프롬프트 상태가 누적되거나 망가지지 않아야 한다.
- 벽, 문틀, 책상, 장치에는 플레이어가 통과하지 못하도록 충돌체를 둔다.
- 문이 열려 있을 때 문짝과 보이지 않는 콜라이더가 통행을 방해하지 않아야 한다.
- 바닥 높이는 기본적으로 동일하게 유지하되 기존 경사·계단 검증용 구역을 별도 테스트 공간에 보존해도 된다.

### 5.3 시각적 블록아웃

- 최종 아트가 없어도 방 기능이 구분되도록 색, 조명, 표식, 가구 실루엣을 다르게 한다.
- 분위기는 어두운 행정기관과 마도 연구소가 결합된 형태로 구성한다.
- 임시 재질은 `Assets/_Project/Art/Prototype/WorldAdjustmentLab/` 아래에 둔다.
- 런타임에 `Resources.Load`로 맵 재질을 조립하지 말고 프리팹과 씬에 직렬화한다.

## 6. 문 시스템

`LabDoorController` 또는 동등한 책임의 컴포넌트를 구현한다.

### 6.1 상태

```text
Closed
Opening
Open
Closing
Locked
```

### 6.2 동작

- 닫힌 문에서 F: 열기
- 열린 문에서 F: 닫기
- 움직이는 도중 중복 입력 정책은 결정론적이어야 한다.
- 기본 열림/닫힘 시간은 약 `0.45초`로 직렬화한다.
- 미닫이 또는 회전식 중 맵에 어울리는 한 방식을 선택한다.
- 문이 닫혀 있을 때는 통행을 막고, 충분히 열린 뒤 통행 콜라이더를 해제한다.
- 닫히는 중 플레이어 또는 NPC가 문 통로에 있으면 닫힘을 중단하거나 다시 연다.
- 문 애니메이션은 프레임 레이트와 무관해야 한다.
- 문 프롬프트는 상태에 따라 `F 문 열기`, `F 문 닫기`, `F 조사하기`로 바뀐다.

### 6.3 잠긴 문

- 잠긴 문은 움직이지 않고 통행을 계속 막는다.
- 상호작용할 때마다 한 번만 잠금 메시지를 표시한다.
- 에러음 연결 슬롯을 제공하고, 기존 UI 효과음 체계가 있으면 재사용한다.
- 현재 격리 연구실 문은 기본 잠김 상태다.
- 이후 진행 플래그로 해제할 수 있도록 잠금 조건을 인터페이스 또는 직렬화 가능한 정책으로 분리한다.
- 이번 작업을 위해 대규모 퀘스트 시스템을 새로 만들지는 않는다.

## 7. 세무관 임시 캐릭터와 8방향 애니메이션

### 7.1 방향 정의

다음 8방향을 명시적인 enum과 데이터 인덱스로 사용한다.

```text
North
NorthEast
East
SouthEast
South
SouthWest
West
NorthWest
```

- 월드의 마지막 유효 이동 방향을 보존한다.
- 실제 표시할 방향은 현재 카메라 quarter yaw를 고려해 화면 기준으로 변환한다.
- Q/E로 카메라를 돌린 후에도 캐릭터 방향 스프라이트가 화면에서 올바르게 보이는지 검증한다.
- 2D 스프라이트 Presenter는 카메라를 바라보되, 물리 루트의 회전과 충돌에는 영향을 주지 않는다.

### 7.2 상태 정의

```text
Idle
Walk
Run
Dash
```

- 각 상태마다 8방향 슬롯을 제공한다.
- 최소 구조는 `4개 상태 × 8방향` 데이터 세트다.
- 각 방향 클립은 `frames`, `framesPerSecond`, `loop` 정보를 가진 데이터 기반 구조여야 한다.
- 권장 기본 속도:
  - Idle: 4 FPS, loop
  - Walk: 8 FPS, loop
  - Run: 12 FPS, loop
  - Dash: 16 FPS, non-loop 또는 대시 지속시간에 맞춤
- 대시가 끝나면 현재 입력 상태에 따라 Idle/Walk/Run으로 정확히 복귀한다.

### 7.3 임시 세무관 스프라이트

- 기존 캡슐만 보이는 상태를 대체할 수 있는 임시 세무관 스프라이트를 준비한다.
- 최종 원화처럼 속이지 말고 `Placeholder` 경로와 이름을 사용한다.
- 8방향과 네 동작의 차이를 플레이 중 눈으로 구분할 수 있어야 한다.
- 코트, 서류가방 또는 세계조정국 배지처럼 세무관임을 알아볼 수 있는 간단한 실루엣을 권장한다.
- 임시 생성 에셋은 `Assets/_Project/Art/Characters/TaxOfficer/Placeholder/` 아래에 둔다.
- 실제 스프라이트 시트가 들어오면 코드 변경 없이 ScriptableObject/프리팹의 참조만 교체할 수 있어야 한다.
- Animator를 사용해도 되지만 32개 상태 전이 폭발을 만들지 않는다. 데이터 기반 Presenter가 더 단순하면 이를 우선한다.

## 8. NPC와 대화 콘텐츠

### 8.1 필수 NPC

- 세계선 분석실에 `세계선 분석 연구원` NPC 1명을 둔다.
- NPC는 상호작용 대상이며 기존 거리·방향·LOS 판정을 사용한다.
- 대화 시작 시 플레이어와 NPC가 서로를 향한다.
- 대화 종료 시 NPC의 원래 방향을 복원한다.
- NPC가 비활성화되거나 파괴되면 대화를 안전하게 종료한다.

### 8.2 임시 대화

최소 4줄의 한국어 대화를 데이터 에셋으로 구성한다. 코드 문자열에 대사를 직접 박지 않는다.

예시 톤:

```text
연구원: 세무관님, 제3관측실의 세계선 변동치가 다시 상승하고 있습니다.
세무관: 승인되지 않은 조정 기록부터 분리해 주세요. 현장은 제가 확인하겠습니다.
연구원: 격리 연구실은 아직 봉쇄 상태입니다. 접근 허가 없이 문을 열 수 없습니다.
세무관: 알겠습니다. 우선 공개된 기록부터 검토하죠.
```

이 문구는 임시 콘텐츠로 표시하고 나중에 교체할 수 있게 한다.

## 9. 양쪽 초상화 대화 UI

### 9.1 화면 구성

1920×1080 기준 하단 대화창을 만든다.

```text
┌ 세무관 이름 ┐                           ┌ 상대 이름 ┐
│             │                           │           │
│ 세무관 초상 │   대화 본문 영역          │ NPC 초상  │
│   왼쪽      │                           │  오른쪽   │
└─────────────┴───────────────────────────┴───────────┘
                                    F / Enter 계속
```

- 왼쪽은 항상 플레이어 캐릭터인 세무관 측이다.
- 오른쪽은 현재 대화 상대 측이다.
- 각 줄의 실제 화자에 따라 해당 초상화와 이름 영역을 밝게 강조한다.
- 말하지 않는 쪽은 약 45~60% 밝기로 낮추되 완전히 숨기지 않는다.
- 초상화는 원본 비율을 유지한다.
- 초상화가 없을 경우 공통 실루엣 플레이스홀더를 표시한다.
- 화자가 시스템/나레이션이면 양쪽을 낮추고 본문만 강조한다.
- 대화창은 다른 HUD보다 위에 표시하고, 중복 생성하지 않는다.

### 9.2 대화 데이터

각 대사 줄은 최소 다음 정보를 가진다.

- 안정적인 화자 ID
- 표시 이름
- 본문
- 화자 측 `Player / Partner / Narration`
- 표정 또는 초상화 변형 ID(현재는 기본값만 있어도 됨)
- 다음 줄 또는 종료 정보

초상화와 이름을 대사 문자열로 추론하지 않는다.

### 9.3 폰트와 테마

- 프로젝트 안에 이미 존재하는 한국어 지원 폰트를 먼저 찾아 재사용한다.
- 외부 폰트를 임의 다운로드하거나 라이선스가 불분명한 폰트를 추가하지 않는다.
- 한국어 글리프가 부족하면 조용히 깨진 글자를 표시하지 말고 명확한 검증 오류를 낸다.
- 프로젝트에 TextMeshPro가 이미 설정되어 있으면 TMP를 사용한다.
- 새 패키지를 설치해야만 TMP를 쓸 수 있다면 현재 UGUI 텍스트 체계를 유지한다.
- 폰트, 크기, 색, 행간, 이름 색, 본문 색, 강조 색, 패널 스프라이트, 초상화 테두리를 `DialogueTheme` 또는 동등한 ScriptableObject에 모은다.
- 1920×1080 권장 본문 크기는 약 32~38px, 이름은 약 28~34px다.
- 1280×720에서도 본문이 잘리거나 초상화와 겹치지 않아야 한다.
- `CanvasScaler`는 기준 해상도 1920×1080과 적절한 match 값을 사용한다.
- Safe Area를 고려한다.

### 9.4 입력과 상태 복원

- F/Enter: 다음 줄
- Escape: 대화 종료
- 한 번 누른 입력은 대사 한 줄만 진행한다.
- 대화 시작에 사용한 F가 첫 대사까지 즉시 넘기지 않아야 한다.
- 대화 중 이동, 달리기, 대시, 일반 상호작용을 잠근다.
- 대화 카메라 오버라이드를 적용한다.
- 종료 후 대화 전 카메라 yaw, zoom, follow 상태와 입력 상태를 복원한다.
- 반복 대화해도 핸들, 이벤트 구독, Canvas 상태가 누적되지 않아야 한다.

## 10. 잠금 메시지와 일반 알림 UI

- 잠긴 문 메시지는 전체 대화창을 열지 않는 짧은 알림/토스트 UI로 표시한다.
- 기본 문구: `접근 권한이 없습니다. 문이 잠겨 있습니다.`
- 약 1.8초 표시 후 페이드아웃한다.
- 같은 프레임에 중복 표시하지 않는다.
- 메시지가 표시되어도 플레이어 이동은 계속 가능하다.
- 새 메시지가 들어오면 기존 메시지를 갱신하거나 표시 시간을 재시작한다.
- 대화 UI와 알림 UI의 책임을 분리한다.
- 글꼴과 색은 공통 UI 테마에서 설정할 수 있게 한다.

## 11. 카메라 구역

- 각 방에는 필요한 경우 `CameraZone` 프로필을 둔다.
- 중앙 접수실은 기본 구도다.
- 기록 보관실은 좁은 통로가 보이도록 약간 확대한다.
- 분석실은 NPC 대화 지점을 프레이밍한다.
- 격리 연구실 외부에서는 잠긴 문과 표식을 함께 볼 수 있게 한다.
- 구역 안에서도 Q/E와 줌 정책이 명확해야 한다.
- 구역 이탈 시 사용자 회전/줌 상태 또는 구역 진입 전 상태를 기존 설계 정책대로 복원한다.
- 겹친 CameraZone은 기존 우선순위 규칙을 유지한다.
- 반복 진입·이탈 시 offset이 누적되지 않아야 한다.

## 12. 세이브 진입과 초기화

- 기존 `Boot → Frontend → Save/New Game/Continue/Load → EntryDestination → 90_GameShell` 흐름을 보존한다.
- `start` SpawnPoint는 중앙 접수실에 둔다.
- 알 수 없는 spawn key를 받으면 임의 위치로 폴백하지 않는다.
- 초기화 실패 시 플레이어 입력을 활성화하지 않는다.
- 씬에 `GameShellRoot`는 정확히 하나만 존재해야 한다.
- 씬에 활성 AudioListener가 중복되지 않게 한다.
- 이번 작업에서 문 상태 저장이 필수가 아니면 억지로 저장 스키마를 확장하지 않는다.
- 잠금 조건을 저장 플래그에 연결한다면 기존 saveVersion, DTO, mapper, migration, repository 테스트까지 함께 갱신한다.
- `PlayerPrefs`를 사용하지 않는다.

## 13. 에디터 제작 도구

다음 메뉴 또는 동등한 도구를 제공한다.

```text
DemonLord/Exploration/Build World Adjustment Lab
DemonLord/Exploration/Validate World Adjustment Lab
```

빌더 요구사항:

- 반복 실행 가능
- 전용 생성 루트만 수정
- 모든 참조 직렬화
- 프리팹과 ScriptableObject 에셋 생성 위치 고정
- 씬 저장 전 검증
- 실패 시 부분 생성 상태를 명확히 보고
- 비개발자도 메뉴 한 번으로 맵과 참조를 재구성할 수 있어야 함

검증기는 최소 다음을 검사한다.

- GameShellRoot 정확히 1개
- `start` SpawnPoint 정확히 1개
- 플레이어, 카메라, 입력, 센서, 대화 UI 참조
- 필수 5개 공간과 문의 존재
- 잠긴 문 정확히 1개 이상
- 대화 가능한 NPC와 대화 데이터
- 세무관 4상태 × 8방향 스프라이트 슬롯
- 한국어 폰트 글리프
- 중복 EventSystem 및 AudioListener
- 비어 있는 필수 초상화/대체 플레이스홀더

## 14. 아키텍처 및 금지 규칙

- 런타임 코드에서 `FindObjectOfType`, `FindFirstObjectByType`, `GameObject.Find`를 사용하지 않는다.
- 서비스 로케이터나 변경 가능한 전역 singleton을 새로 만들지 않는다.
- 씬 참조는 Composition Root에서 직렬화하거나 명시적으로 주입한다.
- `Resources.Load`를 편의상 남발하지 않는다.
- 입력 잠금과 카메라 오버라이드는 소유자가 명확한 disposable handle로 관리한다.
- `Update()`에서 GC 할당이 반복되는 LINQ, 새 배열, 새 리스트 생성을 피한다.
- 상호작용 탐색은 기존 비할당 버퍼 방식을 유지한다.
- 물리 이동, 방향 계산, 스프라이트 표시, 대화 데이터, 대화 화면, 문 상태를 한 클래스에 합치지 않는다.
- 에디터 전용 API는 `Editor` 폴더 또는 Editor assembly에 둔다.
- 새 패키지를 설치하지 않는다.
- Cinemachine이 현재 프로젝트에 없다면 추가하지 않는다.
- 사용자 변경을 되돌리지 않는다.
- 커밋과 푸시를 하지 않는다.

권장 책임 분리:

- `PlayerMotor`: 물리 이동과 대시
- `PlayerFacing`: 월드 기준 마지막 방향 상태
- `DirectionalSpritePresenter`: 카메라 기준 방향 및 프레임 표시
- `DirectionalAnimationSet`: 4상태 × 8방향 애니메이션 데이터
- `LabDoorController`: 문 상태와 애니메이션
- `DoorAccessPolicy`: 잠금 조건
- `DialogueSequence`: 대화 데이터
- `DialogueFocusController`: 대화 세션과 입력 잠금
- `DialogueView`: 텍스트, 이름, 양쪽 초상화 표시
- `DialogueTheme`: 폰트와 시각 설정
- `NotificationView`: 잠금 메시지와 짧은 알림
- `WorldAdjustmentLabSceneBuilder`: 전용 생성 루트 제작
- `WorldAdjustmentLabValidator`: 씬과 에셋 검증

## 18. 최종 보고 형식

작업 완료 후 다음 순서로 보고한다.

1. 실제 플레이 흐름
2. 구현한 방과 연결 구조
3. 문 상태와 잠긴 문 동작
4. 세무관 8방향 애니메이션 구조와 임시 에셋 위치
5. 대화 데이터, 양쪽 초상화, 폰트/테마 구조
6. 기존 결함 수정 내용
7. 추가/수정 파일 목록
8. EditMode/PlayMode 테스트 이름과 정확한 통과 수
9. 1280×720, 1920×1080 QA 결과와 캡처 경로
10. 실제 Boot/New Game/Continue/Load 진입 확인 결과
11. 남은 placeholder와 실제 아트 교체 위치
12. 알려진 위험과 다음 권장 작업 한 가지
13. `git status --short`

다음 표현은 사용하지 않는다.

- 실행하지 않은 테스트를 통과했다고 보고
- ScreenSpaceOverlay가 빠진 캡처를 전체 UI 검증이라고 보고
- 임시 에셋을 최종 아트라고 보고
- 기존 사용자 변경을 이번 작업 결과라고 보고

커밋과 푸시는 하지 않는다.
